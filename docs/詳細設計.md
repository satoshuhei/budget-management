# 詳細設計

## 目的
- 予算管理の基本機能（計画・申請・実行・レポート）を、API/フロントで提供する。
- 監査ログとクライアントエラーログを保持する。
- サンプルデータは状態網羅（ステータスと実績関連）を満たす。

## システム構成
- Backend: FastAPI + SQLAlchemy + SQLite
- Frontend: React + Vite + MUI + DataGrid
- DB: SQLite（budget.db / budget_test.db）
- 開発用サンプルデータ: 起動時シード

## ディレクトリ構成
- app/
  - domain: エンティティ・列挙体
  - application: ユースケース・DTO
  - infrastructure: DB・リポジトリ・シード
  - presentation: API
- frontend/
  - src/pages: 画面
  - src/services: API クライアント
  - src/utils: 変換・ログ
- docs/

## 主要データ定義
### Category / Subcategory
- Category: 予算区分
- Subcategory: 区分内の小分類

### Budget
- 年度・部門・カテゴリ単位の予算
- BudgetAdjustment: 予算調整履歴

### Plan
- 計画（年度・月・分類・金額・種別・状態）
- PlanChange: 計画変更履歴

### Request
- 申請（計画紐付け可）
- 状態: DRAFT / SUBMITTED / RETURNED / APPROVED / REJECTED / CANCELED / CLOSED

### Execution
- 実行（申請紐付け）
- 状態: NOT_STARTED / ORDERED / DELIVERED / INVOICED / PAID / CANCELED
- actual_amount: 実績金額（None または >0）

### BudgetTransaction
- 予算取引（実績反映を含む）
- 種別: COMMIT / UNCOMMIT / ACTUALIZE / REVERT_ACTUAL

### AuditLog
- 監査ログ

## 実績の位置づけ
- 実績は `Execution.actual_amount` と `BudgetTransaction` の ACTUALIZE/REVERT_ACTUAL で表現する。
- サンプルデータの網羅条件:
  - すべてのステータス（Plan/Request/Execution）が1件以上存在
  - BudgetTxType が全種別1件以上存在
  - actual_amount は `None` と `>0` が存在（0は禁止）
  - PAID かつ actual_amount >0 が存在

## シード方針
- 2025/2026 年度に対し、月8件の計画を生成
- ステータス・実績を網羅
- 予算調整、計画変更、監査ログを作成

## API概要
- /api/auth/login, /api/auth/me
- /api/categories, /api/subcategories
- /api/budgets, /api/plans, /api/requests, /api/executions
- /api/reports/*
- /api/client-logs

## フロント概要
- ログイン後、ダッシュボード・計画・申請・実行・レポートを表示
- 金額は日本円フォーマット
- エラーはクライアントログに送信

## 別PCでの起動手順
1. リポジトリを取得
   - git clone <repo_url>
2. Python 仮想環境の作成
   - python -m venv .venv
   - .venv\Scripts\activate
3. 依存関係インストール
   - pip install -r requirements.txt
4. フロント依存関係
   - cd frontend
   - npm install
5. 環境変数
   - ルートに .env を配置（DATABASE_URL は sqlite+pysqlite:///./budget.db）
6. DB初期化（必要時）
   - budget.db を削除
7. API起動
   - uvicorn app.main:app --reload --env-file .env
8. フロント起動
   - npm run dev
